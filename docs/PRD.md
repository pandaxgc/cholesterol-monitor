## 1. 背景与问题定义

### 1.1 背景

用户体检发现胆固醇（LDL-C）偏高，希望在**每晚睡前用 1–2 分钟回顾当天饮食**，并知道当天吃的东西是在帮自己降血脂，还是在推高血脂。

### 1.2 真正的痛点

市面上的饮食记录类产品解决的是"记录"，但血脂管理的瓶颈在**归因与闭环**：

1. **记了没用**：记录了卡路里和菜名，但用户无法把"红烧肉"翻译成"饱和脂肪约 12 g"。
2. **反馈错位**：LDL-C 的变化周期是 4–8 周，按日打分会让用户误以为"昨天吃错了，今天血脂就高了"。
3. **羞辱式设计**：红绿灯评分、打卡中断惩罚会制造焦虑，导致两三周内弃用。
4. **记录摩擦高**：逐条搜索、填克数，晚间疲惫时无法坚持。

### 1.3 产品定位

> 一本只在晚上打开的"血脂账本"：饱和脂肪是每天有预算的货币，每一口都是一笔支出。
> 它不评价你今天好不好，只告诉你**明天省哪一笔最划算**。

### 1.4 记账类比的适用范围

本产品借用记账 App 的心智模型，但以下四点与记账不同，设计上必须区别对待：

| 记账 | 本产品 | 设计后果 |
| --- | --- | --- |
| 金额是精确的 | 营养量是估算的，误差可达三四成 | 界面不显示小数，见 §3.5 显示精度规则 |
| 收入可抵消支出 | 纤维不能抵消饱和脂肪 | 加压项与纤维分开显示，不计算"净值" |
| 余额实时可见 | 血脂只在化验时更新 | 日常只看"支出"，结算放在化验页 |
| 随手记一笔 | 晚上一次补记三餐 | 录入界面按"批量补记"设计，见 §6 |

### 1.5 非目标（明确不做）

- 不做医疗诊断、用药建议，不替代医生
- 不做体重管理、减脂、卡路里记账
- 不做社交、排行榜、勋章体系
- 不做外卖平台接入、食谱电商
- 不做"你的 LDL 会升高 X%"这类伪精确预测
- 不做多账本、多层分类、多账户（MoneyThings 记录繁琐的根源）

## 2. 目标用户与场景

### 2.1 主用户画像

| 维度 | 描述 |
| --- | --- |
| 年龄 | 30–55 岁 |
| 触发事件 | 体检显示 LDL-C 或总胆固醇超标，医生建议"先调整饮食，三个月后复查" |
| 数字素养 | 会用 iPhone 拍照、搜索，用过记账类 App，不愿学习营养学 |
| 时间窗口 | 21:00–23:30，躺在床上，注意力和耐心都低 |
| 核心诉求 | "我到底哪几样东西吃错了？""三个月后复查能不能降下来？" |
| 抵触点 | 被指责、被要求精确填写、被推销 |

### 2.2 关键场景

**S1 · 晚间复盘（每日，主场景）**
躺下后收到提醒，打开 App，今日列表里早餐已按习惯预填。确认早餐，用 One Touch 补上午餐，选一张晚餐照片，看一眼预算余额，读一条建议，关掉。

**S2 · 外食与聚餐（每周 1–3 次）**
火锅、烧烤、宴请。无法知道具体食材，按"吃了什么类型、大概多少"归档，并可把这一天标记为离群日。

**S3 · 三个月复查（低频，高价值）**
拿到新化验单，录入血脂四项，看到这 90 天的饮食均值与血脂变化的对照。

**S4 · 随手一记（偶发）**
白天从小组件或快捷指令点一下 One Touch，记下刚吃的常吃食物，晚上就少补一条。

## 3. 核心产品概念

### 3.1 预算与支出：四项指标

| 指标 | 记账角色 | 每日预算 | 依据 |
| --- | --- | --- | --- |
| 饱和脂肪 | 主预算（支出） | 22 g（约 10% 能量，按 2000 kcal） | 中国居民膳食指南(2022)、AHA/ACC 2018 |
| 反式脂肪 | 零预算（支出） | 尽量为 0，上限 2 g | 中国居民膳食指南(2022) |
| 膳食胆固醇 | 副预算（支出） | 300 mg | 中国居民膳食指南(2022) |
| 可溶性膳食纤维 | 储蓄目标（独立） | 至少 10 g | 中国血脂管理指南(2023) |

- 饱和脂肪是**唯一的主预算**，今日页的大数字只显示它的余额。
- 严格模式下主预算为 11 g（约 5% 能量）。
- 纤维是独立的储蓄目标，**不与支出相抵**。
- 以上阈值在开发前须逐条对照指南原文核实，见 §16。

### 3.2 按次数限额（周预算）

克数难估，次数好记。用户可为食物类别设定每周次数上限，类似记账 App 里"每月喝咖啡不超过几次"。

| 默认建议限额 | 上限 |
| --- | --- |
| 肥肉与加工肉（红烧肉、腊肠、培根） | 每周 2 次 |
| 油炸食品 | 每周 1 次 |
| 奶茶与含植脂末饮品 | 每周 1 次 |
| 动物内脏 | 每周 1 次 |

- MVP 提供以上 4 条默认限额，用户可增删改。
- 一餐内同一类别无论几样食物，只计 1 次。
- 默认限额为产品建议值，不是指南原文，须在界面上如实标注。

### 3.3 食物分级（三级）

| 等级 | 命名 | 判定（每 100 g 可食部） | 视觉 |
| --- | --- | --- | --- |
| A | 友好 | 饱和脂肪 < 2 g | 实心圆点 + 文字"友好" |
| B | 适量 | 饱和脂肪 2–5 g | 半环 + 文字"适量" |
| C | 留意 | 饱和脂肪 ≥ 5 g，或反式脂肪 > 0.1 g，或胆固醇 ≥ 100 mg | 空心圆环 + 文字"留意" |

等级必须同时用图形和文字表达，不得只靠颜色区分。

### 3.4 个人基线与离群日

血脂对饮食的响应个体差异显著，因此 App 以用户自己的历史为参照：

- 以 14 天滚动均值作为"你的日常水位"。
- 反馈优先用相对语言："今天的饱和脂肪比你平时少三成"。
- 热力图的颜色深浅按用户自己的分布分档，不用固定阈值。
- **离群日**：用户可把聚餐、节日等标记为离群日。离群日照常记录和显示，但不计入日常水位，也不触发当日建议。

### 3.5 显示精度规则

食物库存储原始数值，界面显示一律取整，避免假精确：

| 指标 | 显示规则 | 示例 |
| --- | --- | --- |
| 饱和脂肪 | 取整到 1 g，前缀"约" | 约 12 g |
| 反式脂肪 | 只显示"含"或"不含" | 含反式脂肪 |
| 膳食胆固醇 | 取整到 10 mg | 约 90 mg |
| 可溶性纤维 | 取整到 1 g | 约 3 g |
| 百分比 | 取整到 5% 或用"三成""一半"等口语 | 少三成 |

### 3.6 One Touch（一触即记）

One Touch 是一条预先配置好的完整记录：食物 + 份量 + 餐次，点一下即入账。

- 来源：用户手动创建，或 App 根据历史自动推荐"你的高频食物"。
- 出现位置：今日页浮动按钮、份量键盘、主屏小组件；后续扩展到 Apple Watch 与快捷指令。
- 点击后立即入账并给出触感反馈，3 秒内可撤销。
- MVP 上限 12 个。

### 3.7 每日一条建议

每天只给 **1 条**建议，按"预计可节省的饱和脂肪克数 × 可行性"排序：

```
午餐的红烧肉约占今天饱和脂肪的一半（约 12 g）
换成清蒸鱼，预计可省约 10 g
```

建议由规则引擎生成，不使用生成式模型，以保证可解释、可复现、可测试。

## 4. 信息架构

```
Tab Bar（4 项）
├── 今日    ← 默认落地页：预算余额 + 今日流水
├── 清单    ← 智能列表与食物库
├── 分析    ← 热力图、趋势、支出来源
└── 化验    ← 血脂四项录入与对照

今日页右下角浮动按钮组：搜索 / One Touch / 添加
左上角头像 → 设置（预算、限额、提醒、One Touch 管理、数据导出、知识库、免责声明）
```

数据层级只有两层：**类别 → 食物**。餐次是记录的属性，不是层级。

所有页面采用系统原生的分组列表（inset grouped list）。信息密度向 MoneyThings 看齐，层次靠分组、字重和留白建立，不靠卡片和阴影。

**状态矩阵**

| 状态 | 表现 |
| --- | --- |
| 新用户 | 余额显示完整预算；三个餐次分组各显示一行引导文案 |
| 有习惯数据 | 未记录的餐次显示"按习惯预填"的灰色条目，点一下确认入账 |
| 预算用尽 | 大数字改为"已超出约 5 g"，使用警示色，不使用纯红 |
| 离群日 | 标题旁显示"离群日"标签，建议分组替换为"今天不计入日常水位" |
| 全部记完 | 建议分组上方出现"今日已记完"，并播放一次完成反馈 |
| 离线 | 无额外提示（全部数据在本机），仅拍照识别入口置灰 |

**交互**

- 点击大数字 → 展开今日饱和脂肪来源明细，按贡献从高到低排列。
- 条目左滑删除，右滑复制到其他餐次，点击进入编辑。
- 长按条目 → "存为 One Touch"。
- 下拉标题区切换日期；右上角菜单可标记离群日。

### 5.2 清单

承担"账本浏览"职责，全部为列表：

- **智能列表**（系统预置，MVP 不支持自定义）：本周留意级食物、本周限额类别、最近 7 天外食、含反式脂肪的记录。
- **我的常吃**：按使用频率排序，可一键转为 One Touch。
- **食物库**：按类别浏览，类别按使用量排序，支持搜索。
- 食物详情页：四项营养值、等级、数据来源、最近吃过的日期。

### 5.3 分析

顶部分段控件：周 / 月 / 90 天。

1. **热力图**：每天一格，颜色深浅表示当天饱和脂肪支出，分档依据用户自己的分布；离群日用斜纹标记。
2. **趋势**：饱和脂肪日支出折线，叠加预算参考线与 14 天水位线（Swift Charts，无网格线）。
3. **支出来源**：按食物类别累计饱和脂肪排序，显示前 5 项及占比。
4. **限额执行**：各限额类别每周实际次数与上限。
5. 文案小结："过去 30 天，你的饱和脂肪约四成来自烹调油与猪肉。"

提供"排除离群日"开关，默认开启。

### 5.4 化验

- 手动录入：TC、LDL-C、HDL-C、TG、检测日期。
- 折线图展示历次结果，下方并列同期饮食均值。
- 每次录入后生成区间小结：该区间饱和脂肪日均、纤维达标天数占比、限额执行情况。
- 页面必须同时展示："血脂受遗传、药物、体重等多种因素影响，本页仅作记录对照，不构成因果结论。"

### 5.5 设置

预算模式（标准 / 严格）、每周限额、提醒时间、One Touch 管理、份量校准、音效与触感开关、数据导出（CSV / JSON）、知识库、免责声明与依据、关于。

## 6. 核心流程：晚间批量补记

### 6.1 目标

从打开到记完三餐不超过 90 秒；每条记录不超过 3 次点击；全程不需要输入文字。

### 6.2 流程

```
提醒或主动打开
   ↓
今日列表（三个餐次分组，未记的餐次带预填条目）
   ↓
逐餐处理，每餐四种方式任选：
   ├─ 确认预填   点一下灰色条目即入账
   ├─ One Touch  点浮动按钮 ⚡，从面板中点选，直接入账
   ├─ 拍照       选相册照片 → 端侧识别 → 候选食物 → 份量键盘
   └─ 搜索       点 ＋ → 搜索或按类别浏览 → 份量键盘
   ↓
每入账一条，顶部余额数字实时滚动更新
   ↓
三餐记完 → 生成今日建议 → 完成反馈
```

添加面板在提交一条后**不关闭**，停留在当前餐次继续添加，直到用户切换餐次或下滑关闭。这是与"随手记一笔"式记账最大的区别。

### 6.3 份量键盘

参照 MoneyThings 的记账键盘，食物选定后从底部弹出，所有选项都在拇指范围内：

```
┌─────────────────────────────────┐
│ 🍖 红烧肉            约 12 g  ○留意 │  ← 随份量实时变化
├─────────────────────────────────┤
│ [早餐] [午餐●] [晚餐] [加餐]     │  ← 餐次
├─────────────────────────────────┤
│  一小块    小碗    中碗●   大碗   │  ← 该食物的视觉量具
│  ½        ×1●     ×1.5    ×2    │  ← 倍数
├─────────────────────────────────┤
│ [⚡ 存为 One Touch]    [ 记一笔 ] │
└─────────────────────────────────┘
```

- 量具因食物而异：个、片、小碗、中碗、大碗、半盘、一盘、手掌大小。
- 每个量具绑定默认克数，可在设置中校准。
- 默认选中该食物上次使用的量具与倍数。
- 支持左手、右手布局。

### 6.4 拍照识别的降级策略

| 情况 | 处理 |
| --- | --- |
| 置信度 ≥ 0.75 | 作为默认选中项，用户确认即可 |
| 0.4–0.75 | 展示 3 个候选，由用户点选 |
| < 0.4 | 不展示猜测，直接进入搜索，照片保留为该餐配图 |
| 一图多菜 | 一张照片下可挂多个食物条目 |
| 离线或识别不可用 | 入口置灰，其余三种方式不受影响 |

识别失败不得阻塞记录。照片首先是帮助回忆的线索，其次才是识别输入。

### 6.5 边界与异常

- 中途退出：已入账条目即时保存，不弹确认。
- 凌晨记录：04:00 之前的记录默认归属前一天，标题提示"记在 11月13日"。
- 重复添加：同餐次同食物再次添加时合并份量，并提示可撤销。
- One Touch 误触：入账后 3 秒内底部显示撤销条。

## 7. 食物库与数据规范

### 7.1 MVP 规模

- 300–500 条中式常见食物。
- 数据来源优先级：中国食物成分表（第 6 版）> USDA FoodData Central > 厂商营养成分表。
- 每条标注来源与数据版本。

### 7.2 数据模型

食物（Food）：

```json
{
  "id": "cn_braised_pork_001",
  "name": "红烧肉",
  "emoji": "🍖",
  "aliases": ["东坡肉", "扣肉"],
  "category": "fatty_processed_meat",
  "nutritionPer100g": {
    "satFatG": 12.4,
    "transFatG": 0.0,
    "cholesterolMg": 86,
    "solubleFiberG": 0.0
  },
  "grade": "C",
  "servings": [
    { "label": "一小块", "grams": 30 },
    { "label": "中碗", "grams": 100 },
    { "label": "一盘", "grams": 200 }
  ],
  "source": "中国食物成分表(第6版)",
  "dataVersion": "2024.1"
}
```

示例中的营养数值仅用于说明结构，不是经过核实的数据。

### 7.3 聚合与派生

| 派生量 | 定义 |
| --- | --- |
| DailySpend | 某日四项指标合计、各餐小计 |
| Balance | 主预算减去当日饱和脂肪支出，可为负 |
| Baseline | 最近 14 个非离群日的各项均值；不足 5 天时不显示相对语言 |
| WeeklyCount | 自然周内各限额类别的次数，同一餐同一类别计 1 次 |
| SourceRanking | 区间内按类别累计饱和脂肪排序 |
| HeatLevel | 某日支出在用户自身分布中的分档（5 档） |

所有派生量由纯函数计算，不落库，以便单元测试。

## 8. 建议引擎

### 8.1 输入

当日 DailySpend、Baseline、WeeklyCount、预算模式、近 7 天已给出的建议。离群日不生成建议。

### 8.2 优先级规则（自上而下，命中即停）

| 优先级 | 条件 | 输出模板 |
| --- | --- | --- |
| P0 | 当日有含反式脂肪的食物 | "今天的{食物}含反式脂肪，这类成分对血脂影响最大，下次可以换成{替代}。" |
| P1 | 饱和脂肪超出主预算 | "{食物}约占今天饱和脂肪的{占比}（约 {x} g）。换成{替代}，预计可省约 {y} g。" |
| P2 | 某限额类别本周已达上限 | "这周{类别}已经 {n} 次，到上限了。接下来几天可以用{替代}顶上。" |
| P3 | 可溶性纤维不足目标的 60% | "今天纤维约 {n} g。明天加一份{燕麦/豆类/苹果}，大约能补 {m} g。" |
| P4 | 膳食胆固醇超出预算 | "今天胆固醇约 {n} mg，主要来自{食物}，明天减半就在预算内。" |
| P5 | 以上均未命中 | "今天各项都在预算内，照这个结构吃就行。" |

- 同一条建议 7 天内不重复出现；命中的规则若会重复，则顺延到下一优先级。
- 替代食物来自食物库中同场景的 A 级食物映射表。

### 8.3 可解释性

每条建议可展开"为什么"：涉及的记录、计算过程、依据的指南名称。

### 8.4 禁止项

- 不使用"你应该""你违反了"等命令或指责式措辞。
- 不给出药物、补剂、品牌建议。
- 不基于单日数据推断长期风险。

## 9. 视觉规范

### 9.1 基调

安静、克制、原生。看起来像系统自带的 App，细节上比系统 App 多一点温度。

### 9.2 从 MoneyThings 吸收的设计语言

| 吸收 | 落地方式 |
| --- | --- |
| 原生分组列表 | 所有页面用 inset grouped list，不自绘卡片 |
| 大号 Emoji 作为分类图标 | 食物与类别用 Emoji；SF Symbols 只用于功能按钮 |
| 记账键盘 | 份量键盘，见 §6.3 |
| One Touch | 见 §3.6 |
| 热力图千人千面 | 按个人分布分档，见 §5.3 |
| 音效与动效可关闭 | 入账音效、触感、动效各有独立开关 |
| 浮动按钮组 | 今日页右下角：搜索、One Touch、添加 |

| 不吸收 | 原因 |
| --- | --- |
| 三层分类、场景、多账户 | 记录繁琐的根源 |
| 高度可定制的样式编辑器 | 超出 MVP，且增加学习成本 |

以上基于 MoneyThings 的公开介绍与评测整理，尚未对照当前版本截图逐项核实，见 §16。

### 9.3 色板

| 用途 | Light | Dark |
| --- | --- | --- |
| 分组背景 | 系统 `systemGroupedBackground` | 同左 |
| 列表单元 | 系统 `secondarySystemGroupedBackground` | 同左 |
| 主色 | `#1F6F63` | `#4FB3A3` |
| 主文本、次文本、分隔线 | 系统 `label`、`secondaryLabel`、`separator` | 同左 |
| 警示（超预算） | `#C4643C` | `#E08A63` |

- 背景、文本、分隔线一律用系统语义色，保证与系统外观一致。
- 主色只用于可交互元素和余额数字，彩色面积不超过全屏的十分之一。
- 画面里的颜色主要来自食物 Emoji，界面本身保持中性。

### 9.4 字阶

| 层级 | 样式 | 用途 |
| --- | --- | --- |
| 余额数字 | 56pt Bold，SF Pro Rounded | 今日页大数字 |
| Large Title | 系统 `.largeTitle` | 页面标题 |
| Headline | 系统 `.headline` | 分组标题、食物名 |
| Body | 系统 `.body` | 列表正文 |
| Footnote | 系统 `.footnote` | 来源标注、免责声明 |

所有数值启用 `.monospacedDigit()`；除余额数字外全部使用系统文本样式，以支持 Dynamic Type。

### 9.5 间距、形状与材质

- 遵循系统列表默认间距，不自定义行高。
- 食物 Emoji 默认 28pt，可在设置中调整为 24 / 28 / 34pt。
- Liquid Glass 只用于 Tab Bar、导航栏和浮动按钮组；列表内容区为实色。
- 不使用自定义阴影。

### 9.6 动效、音效与触感

| 场景 | 表现 |
| --- | --- |
| 余额数字变化 | `.contentTransition(.numericText())` |
| 入账 | 条目插入动画 + 轻触感 + 可选短音效 |
| One Touch 入账 | `.sensoryFeedback(.success)` |
| 份量键盘弹出 | 系统 sheet，`presentationDetents` 固定高度 |
| 三餐记完 | 一次完成反馈，不做庆祝动画 |

开启"减弱动态效果"时全部降级为淡入淡出。音效默认关闭。

### 9.7 无障碍

- Dynamic Type 支持到 AX5；大字号下列表行改为上下两行布局。
- 等级同时有图形和文字。
- Emoji 设为装饰性元素，VoiceOver 读食物名而不读 Emoji。
- VoiceOver 示例："红烧肉，中碗，饱和脂肪约 12 克，留意。"
- 文本对比度不低于 4.5:1。

### 9.8 夜间优先

- 默认跟随系统外观；提供"20:00 后自动深色"选项。
- 深色下使用系统分组背景，不使用纯黑自绘底色。

## 11. 医学边界与合规

> 本应用用于饮食记录与营养教育，不提供医疗诊断或治疗建议，不能替代医生的专业判断。血脂水平受遗传、体重、运动、药物、疾病等多种因素影响，饮食只是其中之一。请遵医嘱复查与治疗。

## 16. 待决问题

1. **指南阈值核实**：§3.1 的各项预算值与依据须逐条对照指南原文确认，特别是可溶性纤维 10 g 与严格模式 11 g。
2. **MoneyThings 截图对照**：§9.2 基于文字资料整理，需要 2–3 张当前版本截图来确认列表密度、键盘布局与浮动按钮形态。
3. **默认预算模式**：默认标准（22 g）还是严格（11 g）？建议默认标准，录入的 LDL-C 偏高时提示可切换。
4. **默认限额**：§3.2 的 4 条默认限额是否合适，是否需要营养专业人士审阅。
5. **拍照识别方案**：自训练端侧模型还是通用图像分类加人工候选。建议后者先行。
6. **食物库数据授权**：《中国食物成分表》数据的使用方式与授权需确认。
7. **数据导出格式**：建议 CSV 优先（便于给医生看），JSON 作为完整备份。
